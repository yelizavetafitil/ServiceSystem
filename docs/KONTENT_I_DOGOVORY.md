# Как устроены CMS и видимость контента по договорам

В системе **два независимых слоя**. Их нельзя смешивать: настройка «кто видит» не находится в разделах плагинов, видео и туториалов.

---

## Слой 1. CMS — «что существует в системе»

| Раздел админки | Что настраивается | На кого влияет |
|----------------|-------------------|----------------|
| **Репозиторий плагинов** | Регистрация плагина, версии, changelog, загрузка ZIP, активность | Никого напрямую — только каталог |
| **Текстовые материалы (туториалы)** | Заголовок, текст (Markdown), категория, **«Опубликован»** | Пока не опубликован — не попадает в списки видимости |
| **Видеоуроки** | URL/файл, тайм-коды, **«Опубликован»** | То же |

**Зачем отдельно:** администратор один раз создаёт «библиотеку» материалов Белнипи для всех потенциальных заказчиков. Это не привязано к конкретному РУП-облэнерго.

**Аналогия:** склад с инструкциями и дистрибутивами. Положить коробку на склад ≠ выдать ключ конкретному клиенту.

---

## Слой 2. Договор — «что видит организация-заказчик»

| Где в интерфейсе | Путь |
|------------------|------|
| Администрирование → **Договоры и обслуживание** | `/admin/contracts` |
| Ссылка **SLA** у нужного договора | `/admin/contracts/<id>` |
| Блок справа | **«Видимость контента для договора»** |

Три списка с галочками:

1. **Плагины** — какие модули доступны для скачивания по этому договору.
2. **Туториалы** — какие статьи базы знаний видны в ЛК.
3. **Видео** — какие видеоинструкции видны в ЛК.

Кнопка **«Обновить доступ»** сохраняет матрицу в таблицу `contract_content_access` (связь: договор + тип контента + id материала).

**Зачем по договору:** по ТЗ доступ к ресурсам идёт **через договорные отношения** (гарантия / постгарантийное SLA). У Бреста и Вitebsk могут быть разные комплекты плагинов при одной и той же CMS.

**Аналогия:** по договору №060-194-25 клиенту разрешили скачивать только модули A, B, C; по другому договору — полный комплект.

---

## Как это работает для пользователя заказчика

1. Сотрудник регистрируется по **мастер-ключу** организации → учётная запись **наследует `contract_id`** (договор организации).
2. В ЛК при открытии **Плагины / База знаний / Видео** сервер:
   - берёт все **опубликованные** (и для плагинов — **активные**) материалы;
   - **фильтрует** по списку id, разрешённых для **его договора**;
   - скрытое **не показывается** (нет пункта в списке, прямой URL → 403).
3. Скачивание плагина дополнительно проверяет ту же матрицу.

Сотрудники **одной организации с одним договором** видят **одинаковый** набор. Разные договоры одной организации (если их несколько) могут иметь **разную** видимость.

---

## Связь со статусом договора

| Статус договора | Контент в матрице | Поведение |
|-----------------|-------------------|-----------|
| Активен (гарантия / SLA) | Отмечен галочкой | Виден и доступен (скачивание плагинов — да) |
| Приостановлен | Отмечен | Материалы можно **просматривать** где разрешено read-only; **новые заявки и скачивание плагинов** — нет |
| Расторгнут | Любой | **Вход в систему** заблокирован |

Матрица видимости **не заменяет** статус договора: сначала статус (можно ли работать вообще), затем галочки (что именно входит в пакет по договору).

---

## Типовой порядок работ администратора

1. **CMS:** добавить/обновить плагин, статью или видео → включить **«Опубликован»** / активность.
2. **Договор:** открыть карточку договора заказчика → **Видимость контента** → отметить нужные позиции → **Обновить доступ**.
3. (Опционально) **«Применить ко всем договорам организации»** — если у одного РУП несколько договоров и нужен одинаковый набор.
4. Заказчик обновляет ЛК — видит только разрешённое.

Если в CMS материал есть, но **галочка в договоре снята** — в личном кабинете его **не будет**.

Если галочка стоит, но в CMS материал **не опубликован** — в списке видимости админ может его отметить, но в ЛК он **не появится** (фильтр «только опубликованное»).

## Пример (тестовые данные seed)

| Договор | Организация | Видимость |
|---------|-------------|-----------|
| 060-194-25 | Брест | Не все плагины (4 из 5), все туториалы, 2 из 3 видео |
| 060-194-26 | Вitebsk | Полный доступ ко всему опубликованному |
| 060-194-27 | Мinsk | Только 3 туториала, **без** плагинов и видео |

Проверка: войти как `kozlov@brestenergo.by` и `sidorov@vitebskenergo.by` — разные списки в ЛК при одной CMS.

## Краткая схема

```
[ CMS: создать и опубликовать ]  →  материал в общем каталоге
                ↓
[ Договор: галочки видимости ]  →  материал разрешён для contract_id
                ↓
[ ЛК заказчика с этим договором ]  →  только пересечение «опубликовано» ∩ «разрешено договором»
```

Подробнее по шагам в интерфейсе: [INSTRUKCIYA_ADMINISTRATORA.md](INSTRUKCIYA_ADMINISTRATORA.md), раздел «Договоры и SLA».
